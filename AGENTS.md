# AGENTS.md — financial-data-collector

Guidance for any coding agent working in this repo. `CLAUDE.md` points here.

## What this is

A local SQLite warehouse (`data/warehouse.db`) for brokerage positions, cash, transactions,
daily prices and full as-reported SEC financial statements, filled by `fdc sync`. Other
projects consume the database; this one owns collection and storage. Design spec:
`docs/superpowers/specs/2026-09-25-financial-data-collector-design.md`. Implementation plan:
`docs/superpowers/plans/2026-09-25-financial-data-collector.md`.

## Rules

- **Privacy.** `data/`, `inbox/`, `config.toml`, `.env`, `watchlist.txt` are gitignored and must stay so.
  Fixtures are synthetic: invented account names, invented quantities, widely held symbols only.
  Never paste a real balance, label or credential into code, tests, docs or commit messages.
  `tests/test_privacy.py` is the gate.
- **Store owns SQL.** Only `store.py` (and `migrate.py`, `readonly.py`) execute SQL. Adapters and
  collectors produce dataclasses from `models.py`.
- **Schema changes are migrations.** Add `migrations/NNNN_name.sql`; never edit an applied file.
  New statement line items are seed edits in `seeds/concept_map.csv`, not code.
- **No network in tests.** Collectors take `fetch` (and `yf`, `sleep`) as parameters.
- **Idempotent steps.** Re-running `fdc sync` with nothing new must not change data rows. Derived tables are rebuilt from scratch by `derive` and are never a source of truth.
- **The cockpit is a consumer.** `export` writes investing's feed files in investing's shapes; never change those shapes without changing the cockpit first.
- **New feeds live here**, not in consumer projects.
- **A key is never in the repo, the database, a log or a message.** Connections keep keys in the key store (or `.env`);
  every message from a fetcher passes through `connections/redact.py`. Tests use `MemoryKeyStore`; `conftest.py`
  keeps them off the real one.
- **The checker imports nothing it checks.** `check/` reads the warehouse only through `Store.check_*` methods and
  imports nothing from `derive/`, `statements.py` or the collectors (except `http`), so it cannot share their bugs.
  Its outside questions (SEC, Yahoo, Tiingo) are read-only GETs through an injected `fetch`/`outside`; tests never
  touch the network. A hold only ever blanks `valuation_latest`; raw tables are not changed by it.
- **The console only reads.** `fdc console` opens the store once to apply pending migrations, as every command
  does; every refresh after that is a read. The only writer it causes is the `fdc sync` subprocess it starts.
  Strings from outside (a step's message, a path, a service's error) reach the screen as `Text`, never as bare
  strings: Textual reads a bare string's brackets as markup.

## Layout

```
src/financial_data_collector/
  cli.py            fdc init | sync | import | status | query | export | check | mcp | connect | connections | disconnect | accounts | console
  sync.py           runs steps connections -> ingest -> prices -> macro -> sec -> funds -> earnings -> derive -> export -> check -> engine, logs sync_runs (with origin), keeps the heartbeat, exit codes (1 when every network step that ran failed; a skipped connections, macro, funds or earnings step is left out)
  heartbeat.py      data/sync.heartbeat.json: the running sync's step, progress line, pid and origin; wait_for_turn() for a second sync
  console/          model.py (read-only Overview), schedule.py (Windows Task Scheduler reader), actions.py (one fdc sync subprocess), report.py (rich, --once), app.py (Textual screen)
  connections/      names.py (labels, kinds, external keys), keys.py (key store / .env), snaptrade.py + simplefin.py (read-only fetchers -> models), service.py (connect / disconnect / run), redact.py
  derive/           history.py (replay -> holdings_daily, cash_daily, lots, realized_gains, reconciliation, unexplained_daily), valuation.py (valuation_daily), sources.py (pure builders of the `sources` lists engine rows carry: filing links built from CIK + accession, safe feed links), engine.py (the `engine` step's orchestrator: waits for a check run covering the newest derive, reads open holds as missing values (`apply_holds`, `price_holds`, `held_bars`; `held_adjusted_bars`: closes adjusted over every final bar, then held dates dropped), one row per symbol and metric -> valuation_scores_raw, each symbol's drops -> price_moves), shape.py (pure price shape: off the 52-week high, vs the 200-day average, the week against the market and sector funds), scores.py (pure: `percentile` (mid-rank), `band` (`HIGH_IS_PREMIUM` / `HIGH_IS_CHEAP`), `ev_ebit`, `history_scores`: P/E, P/FCF, P/S, EV/EBIT and yield against the company's own 5-year history; `implied_growth`, `cagr`, `fundamental_scores`: ten fundamentals with no band; `read_insider`: the sibling `data/insider.json` feed, read once per run; `fund_scores`: a fund's P/E and yield against its own snapshots, expense ratio), moves.py (pure: `find_moves`: a day down `drop_day`, a week down `drop_week`, or a day down and `excess_sd` of its own sd below the market; `add_causes`: earnings, 8-K (`ITEM_LABELS`), market, sector, news, else "no cause found"), split.py (the weekly split, in progress; `holding_band` (pure: a holding's one band from its primary scores, `PRIMARY_COMPANY` pe, p_fcf, ev_ebit, ps / `PRIMARY_FUND` pe, dividend_yield, each counted only when `ok` with a band; fewer than 2 -> usual, more than half premium -> premium, none premium and more than half cheap -> cheap unless a company's two margin changes are both known and falling; reason codes `held:` `unsupported:` `no_history:` `missing:` `one_metric` `no_metrics` `premium_by:` `cheap_by:` `quality_falling` `quality_unknown` `disagree`; `household_of` (pure: the counted accounts' positions and cash -> `Household`: total, each name's `direct` dollars and its `indirect` dollars through funds with a look-through file; a fund without one is a direct holding of itself; `fund_values`: every held fund's dollars); `cap_used` (a cap's name already held: direct, via files, a fund's own value when the cap is on a fund with a file, and every held fund without a file at the largest weight of the name in any file); `plan_split` (pure: one account's waiting cash -> `SplitPlan(lines, waits, notes)` of `models.SplitLine`; percent gap target% x base - held, top max% x base - held; ratio gap target x via-funds - direct, household-wide; money by gap x tilt, progressive filling inside every band top, sleeve max (its members in the account) and cap (household-wide; a fund line counts its file's weight of the name, a fund with no file the largest weight in any file, `look_through_assumed`); floored to whole dollars, lines under `min_line` folded into the largest line within its room, the rest waits; never more than the cash, never a `hold` or unknown rule; notes `duplicate` `hold` `unknown_rule` `no_look_through` `at_or_over_target` `no_cash` `under_min` `sleeve_cut:` `cap_cut:` `band_top`))
  derive/targets.py the weekly split's two optional owner files, config `[allocation]`: `read_targets` (the targets file -> `models.Targets`: entries with a 0.75x..1.25x band when none is given, sleeves, caps, all in percent (15.0 = 15%) as the file writes them, a `direct_passive_ratio` target a plain ratio; what it skips goes in `problems`; keeps the file name only, never the path; None when the file is missing, ValueError when unreadable) and `read_look_through` (`<FUND>.csv` -> {fund: {held symbol: fraction}})
  check/            the independent checker: __init__.py (CHECKS, CheckContext, run_check), findings.py (Finding), offline.py (fresh, impossible, gaps, closes, recompute; thresholds in config `[check]`), filings.py (SEC lists a filing the warehouse lacks), outside.py (prices2, figures: a second price source and outside statement figures), calendar.py (NYSE trading days), engine.py (`scores`: holds a score with no sources, a link not built the way SEC's are, a percentile outside 0..100 or a band its percentile does not give, by the checker's own band rule; field `score:<metric>`; `ENGINE_CHECKS`, which the `engine` step runs again right after it writes); imports nothing from derive/, statements.py or the collectors
  export/cockpit.py prices.json / dividends.json / fundamentals.json for the investing cockpit
  ingest.py         inbox routing by file signature; SnapTrade folder walk; hash-based idempotency; `read_news` / `ingest_news` (the sibling news feed's headlines)
  adapters/         fidelity_positions.py, fidelity_history.py, snaptrade.py -> models.Snapshot / TransactionRow
  collectors/       prices.py (Tiingo|yfinance), macro.py (FRED: CPI, core CPI, the Fed range, 10-year, unemployment; needs FRED_API_KEY), sec_cik.py, sec_facts.py (EDGAR company facts), yahoo.py (the `YahooClient` seam over yfinance, `default_client()`), funds.py (daily fund snapshots: P/E, yield, expense ratio; a `[fund_proxies]` ETF stands in when a fund has none), earnings.py (report dates from SEC 8-K item 2.02, EPS and surprise from Yahoo, merged by plain rules; daily EPS estimate snapshots)
  sectors.py        SECTORS (the eleven sector names), DEFAULT_SECTOR_ETFS (the fund that stands for each; config `[benchmarks]` builds on them), and `assign_sectors` (a company's sector: the sibling classifications feed, else its SEC SIC code through `seeds/sic_sector.csv`; an unreadable feed keeps the sectors it gave)
  statements.py     facts + concept_map -> financial_line_items (annual, quarter, YTD differencing, derived Q4)
  store.py          Store: every write; migrate.py: migrations, seed, generated wide views
  readonly.py       SQL guard + mode=ro connection; mcp_server.py: schema/query/status tools
  migrations/*.sql  0001 tables, 0002 views, 0003 derived tables + TTM/history views, 0006 connections, 0007 unexplained_daily, 0008 sync_runs.origin, 0009 sec_facts(filed) index, 0010 macro_observations, 0011 prices.final + valuation status columns, 0012 check_runs + check_findings, 0013 valuation_latest applies holds, 0014 securities.benchmark, 0015 fund_snapshots + securities.last_fund_fetch, 0016 earnings_events + estimate_snapshots + securities.last_earnings_fetch / sic, 0017 securities.sector / sector_source, 0018 current_reports + news_headlines, 0019 valuation_scores_raw + the valuation_scores view, 0020 price_moves, 0021 an index of open holds (check_findings by symbol), 0022 allocation_proposals_raw + allocation_lines_raw + their hold-applying views;  seeds/concept_map.csv, seeds/sic_sector.csv
```

## Tables and views (start here when querying)

- `positions_latest`, `holdings_history`, `account_values_daily`, `portfolio_daily` (household total plus `fidelity_total`)
- `prices` (symbol, date, close, adj_close, dividend, split_factor)
- `macro_observations` (series_id, obs_date, value, fetched_at; FRED's own units; series `CPIAUCSL`, `CPILFESL`, `DFEDTARL`, `DFEDTARU`, `DGS10`, `UNRATE`; a revision overwrites the row, "." values are not stored; Claude OS reads it, so keep the names)
- `transactions` (typed: buy, sell, dividend, reinvest, contribution, withdrawal, interest, fee, transfer, other)
- `financials_annual`, `financials_quarterly`, `financials_ttm` (one wide row per company per period; `has_derived_items` marks rows with computed values, `financial_line_items.is_derived` says which)
- `valuation_daily` / `valuation_latest` (market cap, P/E, P/S, P/FCF, dividend yield per price date, using only filings available that day)
- `holdings_daily`, `cash_daily`, `portfolio_daily_full` (replayed from transactions back to the first trade, re-anchored on snapshots; `basis` says which), `lots`, `realized_gains`, `reconciliation`
- `unexplained_daily` (per account and day, the change no transaction or split explains, at least a dollar and not cancelled within a week: `cash`, `holdings` at the day's close, `amount`; most often a deposit the balance shows before the activity feed posts it. A consumer counts `amount` as money moved, not growth)
- `sec_facts` (raw XBRL, every filing's value for every period), `financial_line_items` (shaped), `concept_map`
- `check_runs` (one row per `fdc check` run: `run_id` (start to the millisecond plus six random hex digits, sortable), `started_at`, `finished_at`, `derive_run_id`, `checks_run`, `holds`, `warns` found by that run, `error`) and `check_findings` (what the checks found: `check_name`, `symbol`, `field` = a `valuation_daily` column, `*`, or `score:<metric>` (a `SCORE_METRICS` name, from the `scores` check), `date_from`/`date_to`, `severity` `hold|warn|info`, `message`, `evidence` JSON, `first_seen`, `last_seen`, `cleared_at`; unique on check, symbol, field, date_from). An open hold (not cleared) covering a row NULLs its fields in `valuation_latest` and sets `status = 'held'` (only on a row that was `ok`); `valuation_daily` is never changed by a hold. `fdc check --summary` lists the open ones
- `fund_snapshots` (symbol, date, trailing_pe, forward_pe, dividend_yield, expense_ratio, source, fetched_at; one row per fund per New York day from Yahoo, history starting the day the `funds` step first ran; `source` is `yfinance` or `proxy: X via yfinance` when an ETF named in `[fund_proxies]` supplied the P/E and yield; yields and expense ratios are fractions, 0.0121 = 1.21%; a re-run the same day changes nothing)
- `earnings_events` (symbol, report_date, time_of_day `before_open|during|after_close` in New York time or NULL when only the day is known, accession, eps_expected, eps_reported, surprise_pct in percent as Yahoo gives it (6.74 = +6.74%), date_source `sec|yahoo`, time_source, eps_source; one row per report: the day is the filing date of the 8-K with item 2.02 when SEC lists one (its accession kept), else Yahoo's; EPS from Yahoo; an 8-K up to `MATCH_DAYS` (6) calendar days after Yahoo's day is the same report; old events are kept when SEC's and Yahoo's lists have moved past them, except a Yahoo-dated one with no reported EPS that Yahoo's non-empty list no longer shows, older than MATCH_DAYS: Yahoo moved it) and `estimate_snapshots` (symbol, date, period `0q|+1q|0y|+1y`, eps_avg, eps_low, eps_high, analysts, source, fetched_at; Yahoo's EPS estimates once per company per New York day, history starting the day the `earnings` step first ran)
- `current_reports` (accession, cik, form `8-K|8-K/A`, filed, items as SEC writes them, "2.02,9.01"; every 8-K SEC's submissions list shows for a company, stored by the `earnings` step from the answer it already gets; kept as first stored, never rewritten) and `news_headlines` (symbol, date, title, outlet, url, published, feed_as_of, first_seen; the sibling `data/news.json` feed's headlines, kept by the `ingest` step; the url only when a plain https link; never article text or tags; inputs for drop causes)
- `valuation_scores` (view; read this) / `valuation_scores_raw` (what the `engine` step built): one row per symbol and metric (`SCORE_METRICS`) at the symbol's newest final close: `value`, `percentile_5y`, `band` `cheap|usual|premium` or NULL, `status` `ok|held|unsupported|not_enough_history`, `status_reason`, `inputs` (the valuation_daily columns it was built from as `,pe,`; `,close,` for a price row), `sources` (JSON list of `{kind, label, date, ref[, period][, url]}`), `checked_at` (finish time of the check run that covered the derive it was built from). The engine runs only once a full, error-free check run covers the newest derive (else skipped, rows kept) and reads holds open at build time as missing (closes are adjusted over every final bar, then a held close is left out of every window, so a held ex-date's split still applies; one on the newest day holds the price rows). The view applies holds opened since, in `valuation_latest`'s style: an open hold covering the row's date whose field is `'score:' || metric`, one of `inputs`, or `*` (on a price row only from `prices2`, `impossible`, `closes`) blanks value, percentile and band, makes an `ok` row `held` with the messages as reason, and lists `hold_ids`; the raw table is never changed by a hold. Engine reads are `Store.engine_*`, `final_bars`, `open_holds`, `valuation_rows`, `ttm_rows`, `statement_filing` (the earliest 10-Q/10-K in `sec_facts` reporting a period end). Company history scores (`pe`, `p_fcf`, `ps`, `ev_ebit`, `dividend_yield`) have `inputs` = their own column plus `close` (`,pe,close,`, `,market_cap,close,` for ev_ebit; a `close` hold counts as `*` at build time) and carry `percentile_5y` over the symbol's own `ok`, unheld daily values of `history_years` and a band (`cheap` under `cheap_percentile`, `premium` over `premium_percentile`, mirrored for the yield). The ten fundamentals (`implied_growth`, `fcf_growth_5y`, `revenue_growth_5y`, `fcf_margin_change`, `op_margin_change`, `net_debt_ebitda`, `buyback_yield`, `last_surprise`, `estimate_change_30d`, `insider_net_90d`) have no percentile or band; `implied_growth` names `,market_cap,fcf_ttm,close,`, `buyback_yield` `,market_cap,close,`, `fcf_margin_change` `,revenue_ttm,fcf_ttm,`, `op_margin_change` `,revenue_ttm,`, the rest no inputs (only a `*` hold holds them); holds apply at build time as in the view. A fund (`etf`, `mutual_fund`, `fund`) also gets `pe` (trailing P/E), `dividend_yield` and `expense_ratio` from the newest `fund_snapshots` row dated on or before the day (`unsupported` "no fund snapshot yet" or "newest snapshot is from <date>" when more than `SNAPSHOT_MAX_AGE_DAYS` old), no inputs; `pe` and `dividend_yield` are ranked only among snapshots with the newest one's `source` and get a band only once those span `min_history_days` (else `not_enough_history`, "<N> days of its own snapshots; a band needs 365", value kept) and number at least `MIN_FUND_SNAPSHOTS` (200; else `not_enough_history`, "<N> snapshots of its own; a band needs 200"; short on both, the days reason). `insider_net_90d` and `estimate_change_30d` are `unsupported` when the insider feed's `as_of` or the newest estimate snapshot is more than `SNAPSHOT_MAX_AGE_DAYS` (7) before the day; the estimate's older snapshot must be 30-45 days before the newer. Their reads: `annual_statement_rows`, `earnings_events_of`, `estimate_rows` (one period's snapshots, ascending), `fund_snapshot_rows`
- `price_moves` (symbol, date, span `1d|5d`, start_date, move (a fraction, -0.052), market_symbol / market_move and sector_symbol / sector_move (the funds' moves between the same two dates, NULL without both closes), excess_sd (1d: (move - market_move) / the sd of the 252 bars before, needs 120), triggers `drop_day,excess,drop_week` comma-joined, causes (JSON list of {kind, text, sources}: `earnings`, `filing`, `market`, `sector`, `news` in that order, or one `none` "no cause found"), sources, checked_at): the engine's drops of the last `moves_days`, on closes adjusted over every final bar then held dates dropped; a cause is only stated from a sourced fact. Reads: `earnings_events_of`, `current_reports_of`, `headlines_of`; written by `Store.replace_moves` (rows already right are not rewritten). No hold-applying view: a hold found after the build reaches the moves at the next sync's engine run
- `allocation_proposals` / `allocation_lines` (views; read these) over `allocation_proposals_raw` / `allocation_lines_raw` (the weekly split's proposals: one row per proposal with `account_key` (the targets file's name for the account, never an fdc label), `cash_date`, `cash`, `placed`, `waits`, `status` `open|replaced|spent` (`closed_at`, `closed_cash` say when and with how much cash left), `notes` and `sources` JSON lists, `checked_at`; its lines `symbol`, whole `dollars` (> 0), `target_gap`, `band`, `tilt`, comma-joined `reasons`, JSON `sources`). The raw tables are a RECORD kept like `check_findings`, not derived: a run only adds a proposal or closes one (`replaced` by bigger cash, `spent` when placed), an open proposal's lines are never rewritten, and one account has at most one open proposal (partial unique index). The views apply holds: an open hold of check `split` on field `proposal:<id>` makes an `open` proposal `held` (with `hold_ids`) and blanks its lines' `dollars` (`held` = 1); the raw tables are never changed by a hold. Writes `Store.write_proposal` / `close_proposal` check nothing beyond the schema; reads `split_positions`, `split_cash`, `split_cash_low_since`, `split_scores`, `open_proposal`, `last_spent_proposal`, `check_split_rows`
- `sync_status` / `sync_runs` (each run's `origin`: `scheduled`, `manual`, `console`; `unknown` before migration 0008), `ingested_files`, `securities` (`benchmark` = a yardstick the config names, collected like any symbol, never counted as a holding, left out of the export unless held or listed; `sic` = SEC's industry code, `last_earnings_fetch` = the New York day the earnings step last asked, `sector` / `sector_source` = a stock's or foreign filer's sector and where it came from), `accounts` (with `external_key`, `origin`, `kind_confirmed`, `credit_limit`, `rate_pct`, `flows` for a connected account), `connections`

More examples: `docs/QUERIES.md`.

## Commands

```
.venv\Scripts\python -m pytest            # all tests, no network
fdc sync --dry-run                        # list steps
fdc sync --only prices                    # one step
fdc query "select * from sync_status"
fdc console --once                        # the screen's content, printed once
scripts\open_console.ps1                   # the live screen in its own window
fdc check --summary                       # every open finding of the checker, holds first (runs nothing)
scripts\schedule_check.ps1                # registers the daily 07:00 `fdc check` task (backstop; owner's OK first)
```
