# v0.2 Implementation Plan — TTM valuation, reconstructed history, cockpit integration

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two new `fdc sync` steps: `derive` (TTM/valuation, replayed daily history, lots, realized gains, reconciliation) and `export` (cockpit feed files), plus the investing tickers joining the universe and investing's launcher skipping its own prices/fundamentals feeds.

**Architecture:** Migration `0003_derived.sql` adds the derived tables and static views; `migrate.rebuild_wide_views` gains `financials_ttm`. New packages `derive/` (pure functions over plain rows: `history.replay`, `valuation.build`) and `export/` (`cockpit.py` builders + atomic writer). `store.py` gains read helpers that return plain rows and a generic `replace_rows`. `sync.py` gains the two steps; `cli.py` gains `fdc export`.

**Tech Stack:** unchanged (Python 3.11, sqlite3, pytest). Window functions in SQLite 3.45.

**Spec:** `docs/superpowers/specs/2026-09-25-v0.2-analytics-and-cockpit-design.md` (rules live there; this plan does not repeat them).

## Global Constraints

- Everything in v0.1's Global Constraints still applies (synthetic fixtures, no network in tests, store owns SQL, migrations never edited once applied).
- Derived tables are rebuilt from scratch each `derive` run; they are never a source of truth.
- Export never creates the target directory and never writes a file whose `by_ticker` content is unchanged.
- Version bumps to `0.2.0`.

## Review Focus

1. A symbol held only in a Webull account whose activity window starts mid-life: cash before the first snapshot is a partial sum and must be labeled `reconstructed`, never presented as exact. (Task 3)
2. A company that reports Q4 only in its 10-K (derived Q4 rows) must still form a valid four-quarter TTM window. (Task 1)
3. A price date before any statement was filed must produce no `valuation_daily` row rather than one with a future filing's numbers. (Task 2)
4. A sale larger than recorded lots (history starts after the buy) must record the sale with `cost_known = 0` and not crash or go negative. (Task 3)
5. Export must write nothing when investing's `data/` folder is missing (a clone on another machine). (Task 6)
